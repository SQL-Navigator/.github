Packages and the editor should open on a schema you own, not from mixed folders. Extra units wait for their own title.

## How SQL Navigator Sits

SQL Navigator does not replace the Oracle schema you already keep. It sits beside that engine as named package tools and a SQL editor for a SQL Navigator Oracle desk you own.

If two people share a PC, each keeps a SQL Navigator code session of their own. Extra folders wait for their own title instead of crowding the live units.

## Traffic Light

| Signal | On the SQL Navigator Oracle desk | What you do |
|--------|----------------------------------|-------------|
| Green | Named schema, packages beside the editor | Continue the same code session |
| Amber | Units from two schemas mixed | Split the set before a large change |
| Red | No title, mixed folders everywhere | Stop and name the Oracle desk first |
| Clear | Handoff written, package list short | Close SQL Navigator and leave the desk |

## Open Order

1. Open the last SQL Navigator session on a schema you own, not a new empty navigator.
2. Read the package tools and the last SQL editor.
3. Finish one visible unit inside SQL Navigator package tools.
4. Write what changed on Oracle you own, then close with fewer mixed folders than you found.
5. If the Oracle desk feels crowded, drop anything that belongs to a different schema.

## After a Week

A week in SQL Navigator is not more open folders. It is the same package tools, a shorter SQL editor list, and a note that still makes sense on Monday.

Take finished units off the live set so the next visit starts on the SQL Navigator Oracle desk that is still open.
